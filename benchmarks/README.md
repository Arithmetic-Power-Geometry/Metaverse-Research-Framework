# Benchmarks

Benchmarking begins only after the review identifies sets of methods that solve sufficiently compatible problems.

## Rules

1. Do not compare numerical results copied from incompatible experiments.
2. Reproduce baselines where code and data permit.
3. Record workload, dataset, hardware, network/system conditions, implementation, hyperparameters, random seeds, and metrics.
4. Preserve original reported results separately from reproduced results.
5. Use statistical summaries across repeated runs where stochasticity is present.
6. Introduce a new algorithm only after a documented unresolved limitation is demonstrated under the common benchmark.
7. Keep benchmark outputs machine-readable and generate figures/tables from those outputs.

## Planned benchmark families

Candidate families will be selected after evidence mining. Possible families include:

- computation offloading and service placement
- resource allocation
- XR streaming and rendering adaptation
- semantic communication
- federated/distributed learning
- security/anomaly detection
- identity/trust mechanisms
- interoperability/migration
- digital-twin synchronization
- energy-aware scheduling

No family is considered final until the evidence review confirms adequate comparability.
